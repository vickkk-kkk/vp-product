# VP 服务端实验包使用说明

此包是实验候选，**不是正式版，也尚未通过真实 VPS 验收**。请在已获授权的测试服务器使用，保留现有服务和配置。

## 测试范围

本实验会启动三个 TCP 监听：Trojan TLS、VLESS WebSocket/TLS 和 Shadowsocks AES-128-GCM。转发目标仅限明确允许的公网 IPv4 和端口；不支持任意域名、UDP、IPv6、自动重启或升级。证书使用临时私有 CA，有效期两天。

## 启动前

1. 通过可信的发布渠道核对整个压缩包的 SHA-256，再将其解压到当前运行用户拥有、其他用户不可写的私有目录。包内校验不能替代对压缩包来源的验证。
2. 运行 `./vp-lab check`。它会短暂启动并回收工作进程，不监听端口，也不创建产品状态。通过只表明基本条件满足，不代表 VPS、网络或协议验收通过。
3. 确认服务器有一个本机实际分配的非回环 IPv4 地址和三个未占用 TCP 端口，并按需确认网络访问条件。此程序不会修改防火墙、路由或既有代理服务。
4. 启动前，取得所有者对创建临时测试凭据和监听的明确同意。默认探测请求会联系 Cloudflare，目标服务可以看到服务器来源 IP；也需就此取得明确同意。若未获同意，请停止。

## 前台运行

在当前用户的私有位置创建空目录，权限设为 0700。把下面示例中的地址、端口和路径替换成已确认的值；不要在命令行写入密码或生成的测试凭据。

```sh
./vp-lab run --session-root /绝对路径/空目录 \
  --bind-ip 本机IPv4 --trojan-port 端口1 --vless-port 端口2 --ss-port 端口3 \
  --confirm-test-access --confirm-cloudflare-probe
```

如需在默认 HTTPS 探测目标之外访问其他目标，用 `--target IPv4:端口` 明确列出；每个目标重复一次参数。具体限制及自定义 HTTPS 探测的参数见源码分支的实验部署说明。不会自动配置任何现有客户端。

成功后，私有会话目录的 `output/client-secrets.json` 包含连接测试所需凭据和测试 CA；`output/vault-master.key` 是独立密钥。两者均属敏感资料，不能复制到聊天、日志、命令行、报告或 Release。向其他机器或人员传递凭据前，先获得针对接收方和用途的授权。

保持前台会话运行。测试完成后在该会话发送 Ctrl-C 或 SIGTERM，并确认测试监听关闭。当前不支持恢复该会话或自动重启。失败或状态不明时保留隔离目录并报告脱敏错误，不要盲目删除、重试或停止无关进程。清理凭据和目录前按需取得授权。

## 从另一台机器验证

外部机器也需要同架构且满足相同基本系统要求。经所有者明确许可后，通过安全渠道将 `client-secrets.json` 交给该机器上的运行用户，保存为仅该用户可读的 0600 文件；不要把文件内容放在命令行、聊天或报告中。不要复制 `vault-master.key`。

在另一台机器解压并核对同一个包后，运行 `./vp-lab check` 检查基本环境。取得所有者对向指定服务器使用测试凭据、以及通过服务器访问 Cloudflare 的明确同意后，运行：

```sh
./vp-lab client --credentials-file /绝对路径/私有凭据文件 \
  --server-ip 服务器公网IPv4 --confirm-credential-use --confirm-cloudflare-probe
```

外部验收客户端当前只支持通过 Cloudflare 目标做 HTTPS 检查；若部署时改用了自定义探测目标，需要同时明确允许 `1.1.1.1:443`，否则客户端会拒绝测试。

客户端逐项报告三个协议是否通过真实 HTTPS 状态检查；`not_verified` 只表示没有验证成功，不能单独说明是认证拒绝还是网络故障。此客户端复用同一套核心，不能替代独立客户端互通测试；不能从服务器本机测试推断公网入口可达。
