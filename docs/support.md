# 支持状态

状态针对 **PrivateVP 整合后的产品**，不是上游项目能力清单。已有组件测试按精确代码身份登记；尚未登记不代表旧工作不存在，也不代表产品验收已经完成。

## 组件与平台

| 范围 | 已知基础 | 产品目标 | 当前产品验收 |
| --- | --- | --- | --- |
| Windows / Linux 桌面客户端 | vpn-parser 的 Rust / egui 源码基础 | 统一多引擎 UI、独立适配与生命周期 | 待 fork 构建与各平台实测 |
| macOS 桌面客户端 | 选定 Rust / egui 技术路线 | 与其他桌面端保持一致的业务行为 | 待平台集成与实测 |
| Android 客户端 | 共享 Rust 层抽取方向已确定 | 原生 VPN 生命周期与多引擎接入 | 待完整集成；不能以桌面测试替代 |
| iOS 客户端 | 共享 Rust 层抽取方向已确定 | 原生隧道扩展与多引擎接入 | 待平台环境、签名条件与完整验收 |
| Linux 服务端 | 已有管理服务、控制层、核心适配与候选实现 | vp_core 服务端及可靠生命周期 | 已纳入源码，待新目录完整构建与回归；非生产部署承诺 |
| Web 管理端 | 已有 Flutter Web 管理源码 | 通过管理 API 配置与观察服务端 | 已纳入源码，待新目录构建与联调 |
| 安装 / 升级 | 已有本地 bundle 工具与不同版本流程 | 可核验、可恢复的 Linux 交付 | 不同 bundle 流程需分别验收 |

“计划支持”不是“已支持”。上游已有集成、独立引擎实验、版本探测和接口注册都不自动转换成新 fork 的产品通过记录。服务端的引擎边界仍为 vp_core，不随客户端多引擎目标扩大。

每个引擎 / OS 组合须单独覆盖：配置合法性、真实 TCP/UDP 流量、切换、停止后资源释放、后台行为与失败恢复。还要记录不支持的协议、模式和系统版本；不能用另一个引擎的结果填补。

## 已有验证的准确范围

客户端定制源码检查点固定为 `09f1bbbe02d39be13a6119059845485a1d06738d`，包含完整 parser、更新器保护、移动端导入与字体资产，以及六套共享配置编译器与移动端配置预览。

- 此前实际 workspace core 默认测试 **102 项通过**：76 单元 + 26 集成；其中一个隔离 golden 测试比较六套编译器与旧实现的合成输出。
- Rust 1.88、根 features=[] 的 Linux headless harness 此前常规增量编译后，**11 个指定纯逻辑测试通过**；core 与这 11 项测试对应代码未被本次预览改动改变。
- 移动端默认纯逻辑测试 **27 项通过**（12 配置预览 + 15 既有），67 包依赖图未变。
- ab_glyph 对 **63 个字形**的软件栅格检查通过，仅验证字体资产，不是 egui 或原生平台渲染验收。

移动端源码已接入显式引擎/节点选择、经检查但不可直接运行的配置预览与凭据默认隐藏、明确选择后显示。它们不等于经过 GUI 验收；共享六套配置编译器也不等于六个移动端原生运行时已经可用。没有运行实时 collector、网络请求、主程序、GUI 或引擎运行时；告警保留，不宣称 warning-clean。

About 界面相关变更仅通过静态审查，未进行 GUI 编译。日志修复仅覆盖 `collector/mod.rs` 的诊断日志，存储与 UI 错误未改变。主仓已锁定定制源码，但完整测试套件、GUI、移动端与原生 VPN 验收尚未完成；源码检查点不等于正式二进制发行版。详见 [当前快照](source-snapshot.md)。
